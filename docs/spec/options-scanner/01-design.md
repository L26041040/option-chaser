## 0. 一分鐘看懂

使用者選一個股票範圍（例如美國前 500 大），系統做三件事：

```
 ① 共識篩選                    ② 產生劇本                 ③ 選擇權搜尋與排序
 每檔股票的個別分析師目標價      通過的股票：                現有 Option Chaser 引擎：
   → 平均、標準差、分歧度        目標價 = 分析師平均目標價    窮舉合格策略 → 成本、損益、
   → 兩道門檻都過才留下          目標月份 = 依規則對應        報酬倍率、最大損失 → 過濾
                                                           → 跨標的排序
```

- ① 是新的（需要分析師資料源）。
- ② 是一個很薄的轉換：把共識變成現有的 **Scenario（劇本）**。
- ③ **完全沿用現有引擎**：現在使用者手動填劇本時跑的那套計算，原封不動。

所以這個功能的本質是：**由系統自動幫使用者產生一批高共識的劇本，再把每個劇本的最佳候選放在
同一張表上比較。**

### 1.1 與現有產品的關係

現有產品的定位是 **Scenario Bet Ranking**：「如果我的價格劇本成立，哪個 Candidate 的成功情境
報酬最好」。搜尋器**不改這個定位**，只多了兩件事：

| | 現有產品 | 搜尋器 |
|---|---|---|
| 劇本從哪來 | 使用者自己填 | 分析師共識自動產生（**Consensus Scenario**） |
| 比較範圍 | 一個劇本內的候選 | **跨標的**：每個通過標的的最佳候選放在一起排 |
| 排名口徑 | 成功情境報酬（成本＝最差可成交價） | 相同 |

## 2. A — 分析師共識演算法 ✅

### 2.1 計算

對每檔股票，取「目前有效」的個別分析師目標價 `TP₁ … TP_N`（每位分析師一筆）：

| 量 | 公式 | 說明 |
|---|---|---|
| 平均目標價 | `TP_mean = (1/N) · Σ TPⱼ` | 通過篩選後，這就是劇本的目標價 |
| 標準差 | `σ_TP = stdev(TPⱼ)` | 樣本或母體標準差：❓（見 §2.4） |
| 標準化分歧度 | `D = σ_TP / TP_mean` | 例：平均 120、標準差 9 → `D = 7.5%` |

### 2.2 兩道篩選門檻（兩關都過才採用）

| 關卡 | 規則 | 預設 | 可調 |
|---|---|---|---|
| **第一關：自身歷史百分位** | 今天的 `D` 在**這檔股票自己**的歷史分歧度序列中排在最低的 X% | **20%** | ✅ Settings，可自由調整 |
| **第二關：絕對分歧上限** | `D ≤ Y` | **10%** | ✅ Settings，可自由調整 |

- 兩個門檻**各自獨立可調**，不得寫死。
- 為什麼要兩關：第一關抓「這檔股票現在比平常更有共識」；第二關擋掉「本來就吵成一團、只是比
  平常好一點」的股票。

**第一關的算法**

1. 這檔股票的歷史分歧度序列 `D_t`：在過去每個取樣日 *t*，用**當時**有效的個別目標價重算一次
   `D`（取樣頻率、回看長度：❓ §2.4）。
2. 百分位 = 歷史序列中 `D_t ≤ D_今天` 的比例。
3. 百分位 ≤ 門檻（預設 20%）→ 通過。

例：某股票過去 60 個月的 `D` 有 9 個月低於或等於今天的值 → 百分位 = 15% → 通過第一關。

### 2.3 資料品質條件（必要的最小集合，不擴充成預測模型）

Owner 指示研究「最低分析師人數、資料新鮮度等必要資料品質條件」。老弟建議只放下列四項，
全部是**資料夠不夠算**的問題，不是預測：

| 條件 | 為什麼需要 | 建議預設 | 狀態 |
|---|---|---|---|
| 最低分析師人數 `N_min` | 3 個人的標準差沒有意義 | 5 | ❓ |
| 目標價有效期 | 多久沒更新的目標價不算「目前有效」；太舊的目標價會虛增分歧 | 發布後 12 個月內（或資料源的 active 標記） | ❓ |
| 新鮮度 | 整組共識都很舊時，平均目標價可能已經被行情超過 | 至少一半的目標價在近 90 天內更新 | ❓ |
| 最短歷史 | 歷史點太少時，百分位不可靠 | 至少 24 個月度取樣點；不足時**不通過第一關** | ❓ |

### 2.4 計算細節（待決策，見 Wayfinder 票「共識計算的資料品質與歷史取樣規則」）

- 標準差用樣本（n−1）還是母體（n）。
- 歷史序列的取樣頻率（建議月底）與回看長度（建議資料源可得的全部，上限 5 年）。
- 股票分割：分割前發布的目標價必須換算到同一基準，否則當期 `D` 會失真。
- 單一極端目標價是否處理（Owner 指定用平均；是否另外做截尾是 Owner 的決定，預設**不做**）。

## 3. B — 選擇權搜尋 ✅

### 3.1 把共識變成劇本（Consensus Scenario）

通過兩關的股票，產生一個與現有 **Scenario** 相同形狀的劇本：

| Scenario 欄位 | 值 | 狀態 |
|---|---|---|
| `symbol` | 該股票 | ✅ |
| `target_price` | 分析師**平均**目標價 `TP_mean` | ✅ |
| `target_month` | 由「12 個月目標價 → 月份」規則決定（§3.2） | ❓ |
| `best_price`／`worst_price` | 選填：最高／最低個別目標價（現有三價位對照會自動顯示） | ❓ |
| `strategies` | 使用者在 Settings 選的策略家族 | ✅ 可設定 |
| 方向 | 由 `target_price` 相對現價自動推導（現有規則：看漲／看跌／持平） | ✅ 沿用 |

### 3.2 預測期限與到期日

分析師目標價慣例是 **12 個月**目標。現有劇本的時間語意是**月級**（`target_month`），引擎再用
既有的**六點規則**，從實際到期日中挑出距該月第三個星期五最近的 baseline，加上前後各兩檔，
最多五個到期日一起搜尋。所以只需要決定**目標月份**：

| 選項 | 做法 | 特性 |
|---|---|---|
| (a) 固定 12 個月 | 目標月份 = 今天 + 12 個月 | 最簡單；忽略目標價已發布多久 |
| (b) 扣掉已經過的時間（老弟建議） | 目標月份 = 個別目標價發布日的中位數 + 12 個月 | 目標價平均已發布 3 個月 → 目標月份是 9 個月後；較貼近分析師的本意 |
| (c) 使用者指定 | Settings 選固定期限（如 6／9／12 個月） | 彈性最大；與分析師的 12 個月語意脫鉤 |

此為 ❓ 待決策。不論哪個選項，都**不需要**新的時間概念：仍然是月級的 `target_month`，
`CONTEXT.md`「不要說目標日期」的紀律不變。

### 3.3 窮舉、計算、過濾（全部沿用現有引擎）

| 步驟 | 現有能力 |
|---|---|
| 窮舉 | 三個策略家族（Call／Put、Vertical Spread、Butterfly）在選出的到期日上窮舉 |
| 成本 | 最差可成交價（買腿 ask、賣腿 bid） |
| 損益與報酬倍率 | 目標價情境報酬 `baseline_return`、損益兩平、最大獲利 |
| 最大損失 | Debit 結構＝成本 |
| 流動性與報價健全性過濾 | 既有的報價檢查、買賣價差上限（`max_spread_pct`）、IV 檢查、結構檢查 |
| 使用者條件 | ❓ 搜尋器是否新增條件（例如最低成本、最大損失上限）——待決策 |

### 3.4 跨標的排序

每個通過的標的會得到每個策略家族的代表候選（現有的 Per-family Representative）。搜尋器把
所有標的的代表候選放在一起排序。

- 預設排序指標：**目標價情境報酬**（與現有產品頭條數字同一口徑）❓
- 每檔股票預設顯示幾個候選、是否允許依成本或最大損失排序 ❓

### 3.5 條件情境報酬 ≠ 完整期望值 ✅

搜尋器顯示的報酬，是「**如果**股價在目標月份到達分析師平均目標價」的報酬。它**不是**期望值，
也不是獲利機率。產品文案不得把它稱為期望報酬、勝率或預期獲利。

歷史達標機率（例如「過去通過雙門檻的股票，12 個月後到達目標價的比例」）可以作為**日後的
研究題**，不是這個功能的前提，也不建立新的機率分布模型。

## 5. 使用流程（草案，細節待原型票）

1. 使用者在 Settings 設定搜尋母體與兩個門檻（有預設值，不設也能用）。
2. 進入「機會搜尋」頁，看到通過共識篩選的標的清單（平均目標價、分析師人數、分歧度、
   自身歷史百分位）。
3. 按「搜尋選擇權」，系統對通過的標的逐一跑現有引擎，結果逐檔出現（沿用現有的續跑機制）。
4. 結果表：每列一個機會（標的、策略、履約價、到期日、成本、最大損失、目標價情境報酬、
   損益兩平）。
5. 點任一列 →「存成劇本」，變成一個普通的 Scenario，進入現有的詳細頁（Heatmap、三價位
   對照、Historical IV 等全部可用）。
