## 1. 修訂後的一句話

> 先用一個**有停損點的研究回測**回答：「分析師共識訊號，扣掉選擇權溢價與交易成本之後，
> 還剩不剩超額報酬？」答案是「剩」，才談產品。

和 v0 的主要差異：

| 項目 | v0 | 修訂後 |
|---|---|---|
| 第一步 | 建模型 | **先過資料閘門**（Phase 0） |
| 核心問題 | 預測達標機率 | 證明 **P 比 Q 準**，且超額報酬撐得過成本 |
| 母體 | 前 500 大＋100 檔 ETF | 研究期只用**當日** S&P 500 個股；ETF 排除 |
| 結構 | Call、Put、Debit Spread | 研究期只用 **Long Call＋Bull Call Spread** |
| 持有 | 到期＋提前出場 | 只做**持有到期** |
| 市場環境 | 模型的分箱維度 | **壓力測試**（逐事件報告），不估參數 |
| 結果變數 | 原始達標率 | **相對大盤的超額報酬**＋原始值並列 |
| 排序 | EV%、倍率 | 扣除不確定性後的 EV（例：EV 信賴區間下界），設最低成本 |
| 分歧度 | 唯一主角 | 與 `age`（目標價新舊）一起當一級特徵 |

## 5. MVP 建議（研究型 MVP，不是產品功能）

### 5.1 範圍

| 項目 | MVP |
|---|---|
| 母體 | **掃描日當時**的 S&P 500 成分個股（含後來下市者） |
| 結構 | Long Call、Bull Call Spread（只做看漲；看跌待 v2） |
| 天期 | 單一天期（建議最接近 180 天的月選） |
| 持有 | 只做持有到期 |
| 頻率 | 每月一次掃描（分析師訊號本身是低頻） |
| 輸出 | 研究報告，不上線、不給使用者看 |

### 5.2 所需資料

| 資料 | MVP 最低需求 | 來源候選 |
|---|---|---|
| 歷史成分 | S&P 500 每月成分 | 待查（公開來源或資料商） |
| 個別目標價 | 2021 起，含發布日 | FMP（平價）；同時開始自行保存快照 |
| 股價 | 日線，含分割、除息與下市調整 | 現有或平價資料商 |
| 選擇權 EOD | 含 bid/ask，與目標價同期 | ORATS／Alpha Vantage 等（需報價） |

### 5.3 回測方案

1. **Walk-forward**：每個掃描日只用之前的資料估分布；第一段保留為訓練期，之後逐月滾動。
2. **Point-in-time**：只用發布日 ≤ 掃描日 − 1 個交易日的目標價；母體用當日成分。
3. **條件式分布**：先用最簡單的版本——依 `u`、`D`、`age` 三個特徵各分 3 組（共 27 格）的
   經驗報酬分布；樣本不足的格子合併，不做複雜模型。
4. **候選與成本**：每檔取一個固定 delta（例如 0.30）的 Call 與一個固定寬度的 Spread；買腿 ask、
   賣腿 bid、含手續費；設最低成本與最大價差 %。
5. **排序與投組**：依 EV 信賴區間下界取前 N 名，等權重。
6. **對照組**（每一個都必須跑）：
   - 隨機選擇權（同天期、同 delta）
   - 不用分析師特徵的同一套模型（只用基本率）
   - 同訊號的股票版本
7. **統計**：按日期群集的穩健標準誤（天期重疊會讓樣本高度相關）；或用區塊 bootstrap。
8. **壓力測試**：逐事件報告（2021 起的資料至少涵蓋 2022）。

### 5.4 成功判準（全部事先登錄，結果出來後不得修改）

| 判準 | 門檻 |
|---|---|
| 校準 | §3 H2′ |
| 經濟效益 | §3 H3′ 與 H4′ 同時通過 |
| 穩健性 | 改變分組切點 ±1 檔、天期換成相鄰月份，結論方向不變 |
| 極端行情 | §3 H5′ |

### 5.5 停損點（任一成立就停）

1. Phase 0 拿不到可接受成本的 point-in-time 目標價**且**選擇權歷史報價。
2. 校準失敗（H2′）。
3. 選擇權版本打不贏隨機選擇權（H3′），或打不贏股票版本（H4′）。

### 5.6 階段

| 階段 | 內容 | 產出 | 進下一階段的條件 |
|---|---|---|---|
| Phase 0 | 資料閘門：實際報價、樣本、覆蓋率、授權條款；同時開始自行保存目標價快照 | 資料可行性報告 | D2、D3 有可接受的答案 |
| Phase 1 | 離線回測（§5.3） | 回測報告＋校準圖 | §5.4 全數通過 |
| Phase 2 | 才決定產品形態（D1）與是否擴到 Put、ETF、提前出場 | 產品規格 | Owner 決定 |

## 6. 老弟對 D1 的建議理由（劇本產生器）

- **工程成本最低**：現有引擎已會「給一個劇本 → 產生並排序候選」。掃描器只要新增「劇本來源」
  （共識目標價＋目標月份），不需要新的排序口徑，也不需要條件式分布模型才能先給使用者東西。
- **不破壞現有定位**：Scenario Bet Ranking 的口徑不變；分析師共識只是「誰提出劇本」。
- **研究與產品解耦**：Phase 1 的機率模型如果驗證成功，再以新的 bounded context 加上 POP／EV；
  驗證失敗，劇本產生器仍然是一個誠實的功能——它只說「如果分析師是對的」，不宣稱機率。
- **風險**：使用者可能把「分析師劇本」誤讀為「推薦」。需要清楚標示來源與歷史達成率（C1）。
