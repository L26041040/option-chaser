2. Wayfinder 必須拆清楚的七塊

A. 匿名使用者身份

白話問題：

* 第一次進網站，我們怎麼知道「這是這個人」？
* Cookie 裡到底存什麼？
* Server 怎麼把 cookie 對到 owner？
* Cookie 被偷會發生什麼？
* 清 cookie / 換瀏覽器 / 無痕模式後會怎樣？
* 要不要 recovery code？
* 未來匿名使用者要升級成正式帳號，資料怎麼接過去？

不要直接假設「完整註冊系統比較專業」。

⸻

B. 資料生命週期 / 自動清理

這是本輪核心之一。

匿名使用者很容易留下大量永遠不會再回來的資料。

要回答：

* 多久沒有活動才算 abandoned？
* Scenario / results / snapshots / events 各自是否需要不同 retention？
* 哪些資料可以刪？
* 哪些資料因為 audit / replay / shared market facts 不應跟著 owner 刪？
* soft-expire → grace period → hard delete 是否比較安全？
* 使用者重新回來時 expiry 是否刷新？
* 如何避免 DB 被大量匿名垃圾資料慢慢塞滿？

⚠ 不要自己拍腦袋決定「30 天刪除」。

需要研究成熟做法再 Grill Owner。

⸻

C. Abuse / Loading / 成本控制

匿名使用最大風險之一不是 privacy，而是：

一個人可以一直開新 cookie、一直建立 Scenario、一直 refresh，燒 vendor quota / DB / compute。

要拆：

* 每個 anonymous owner：
    * Scenario 數量上限？
    * refresh 頻率？
    * 每日分析量？
* IP / browser / owner 三種限制各有什麼優缺點？
* rate limiting 應在哪一層？
* 如何避免 retry storm？
* 如何處理惡意使用但不誤傷普通使用者？
* 哪些限制應該一開始就存在，哪些可等真的有 abuse 再做？

## 最重要的 10 個發現

1. **12 個成熟免登入產品裡，沒有一個現行仍在運作的產品，同時具備「伺服器
   端記住匿名使用者物件」＋「代匿名使用者呼叫按量計費第三方 API」這兩個
   特徵**（#274）。Replit／CodePen／CodeSandbox 都曾放寬匿名權限後因濫用
   經濟學收緊，且它們燒的是自己的運算資源，不是像本產品這樣代打外部
   vendor API——找不到可以直接照抄限流數字的先例。
2. **美股選擇權報價著作權屬於 OPRA（交易所聯合報價機構），且 OPRA 對
   「延遲 15 分鐘以上」資料不收逐訂閱者費**（#290）——Option Chaser 現行
   本來就是延遲報價產品，代表選對合法 vendor，使用者數增加不必然推高
   授權成本。
3. **確實存在合法替代資料源**：Intrinio Silver Options 官方原話明文允許
   「顯示給企業終端使用者、不逐使用者收費、無需交易所額外手續」，精準
   對應本產品用法（#290）。
4. **Vercel 官方行為是 push master 一律直接部署，沒有任何官方機制能讓
   Vercel 等外部 CI 綠燈**——真正能擋的關卡是 GitHub 自己的 branch
   protection「required status checks」（公開 repo 免費），把關點在合併
   按鈕、不在 Vercel（#280）。
5. **Neon Free 主控台圖表只留 1 天、無內建告警；Vercel Hobby Runtime Logs
   只留 1 小時**——證實本站既有的 `operational_metrics`／`chain_backoff`
   自建機制不是過度工程，是免費層唯一能看到「這週發生了什麼」的方式
   （#278）。
6. **匿名身份 cookie（隨機 id＋伺服器查表）法規風險極低**，明確落在
   ePrivacy「strictly necessary」豁免（#279）。
7. **推翻一項過時認知**：英國《Data (Use and Access) Act 2025》已於
   2026-02-05 生效，新增類似法國 CNIL 的「統計用途例外」，英法兩地
   Analytics 免同意條件現已趨於一致（#279）。
8. **既有「非投資建議」免責聲明只活在收合的 Advanced 區塊，陌生人首次
   進站看不到**，弱於同類金融工具（OptionStrat 用常駐頁尾）（#279）。
9. **LINE Notify 已於 2025-03-31 正式終止**（官方公告，非傳聞）——不是
   還能用的通知管道（#280）。
10. **Alpha Vantage／Polygon／MarketData.app 現有方案／Finnhub／Twelve

## 哪些改變 Release Architecture

- **部署流程要從「有時直接 push master」改成「開 PR → CI 過 → 手動合併」**
  ——這是唯一能讓 CI 真正發揮擋人效果的做法，Vercel 本身擋不了（#280）。
- **`owner_credentials` 的第三方 token 清理，建議獨立於一般 retention 天數、
  優先處理**（Batch 1 #276 既有發現，Batch 2 未推翻）——這比「資料留幾天」
  更急迫，因為閒置 owner 的 token 是持續有效的安全曝險。
- **市場資料源可能整個要換**——若 Owner 決定要走合法路線，engineering
  frontier 多一項 I10（見下方地圖更新），現有 `providers.py` 白名單＋
  adapter 抽象撐得住多數候選，但需處理 Intrinio 禁止散裝下載與既有 CSV
  匯出功能的衝突。
- **維運告警不需要新建即時儀表板**，延伸既有 `operational_metrics`／
  `chain_backoff` 機制＋每日摘要＋唯二外部工具（Sentry、UptimeRobot）
  即可，把原本設想中「要建一個 Admin Dashboard」的範圍收窄。

## 真正的 Public Beta Blockers

- **身份隔離（I2/I9/I3）**——今天全站只有一個 `solo` 身份，任何人找到
  網址就能互看互刪，這是現況不是風險（Batch 1 已知事實 #1，本輪未變）。
- **額度／保險絲（I4）**——沒有 per-owner 限流、沒有劇本數上限，且業界
  找不到結構相同的先例可以照抄數字（#274 補強 #277 既有發現）。
- **清理機制（I5）**——完全沒有「刪掉一個 owner 全部資料」的操作。
- **最低可見性（I6）**——Sentry＋UptimeRobot 判定 Beta-blocking，因為
  平台免費層的紀錄保留期太短，出事後幾乎無法追溯。
- **CI＋branch protection（I1）**——沒有這一層，「測試綠燈」只是紀錄用，
  擋不住任何東西。
- **合法市場資料源（新增，I10）**——若 Owner 決定要處理，這是額外一項

  在追蹤這個決策本身**，需要 Owner 明確指示。
