Final Owner Decisions

OD-06 Historical Raw Snapshot

Raw option-chain snapshot 永久保存。

理由：

* 它是不可重新取得的市場事實
* 是未來 historical re-analysis 的 canonical seed
* storage 成本未來若變大，解法是搬到較便宜的 archival/object storage
* 不是刪除 seed

Foundation 階段先維持現有 storage location，不新增 object-storage dependency。

⸻

OD-07 Historical Candidate Trend

歷史走勢只 materialize 使用者實際可點到的 candidate：

* 各 expiry visible top candidates
* 保存最小窄資料：
    * scenario_id
    * analyzed_at
    * candidate_key
    * cost

必要時可以加入為 correctness 所需的最少 key，但不得把完整 candidate object 重新塞回去。

這份 narrow history 永久保存，暫不設 retention。

⸻

OD-08 Diagnostics Ownership

Diagnostics 視為 user-scoped operational data。

未來 ownership boundary 建立時：

* diagnostics 必須能依 owner 隔離
* 不允許不同 user 從 diagnostics 看見彼此的 symbol / scenario activity

Canonical Storage Principle

Spec 必須明文寫入：

保存不可確定性重建的 seed + provenance + version；
deterministic derived output 原則上不永久保存，除非它位於高成本 read path、必須 materialize。

資料分層：

* L0 Seed
* L1 Provenance / Version
* L2 Materialized Derived
* L3 Pure Derived

並明確列出各資料類型歸屬。

⸻

Storage Migration Hard Sequence

不得跳步：

Stage 1-0 — Extract reconstruction seed

先把目前寄生在 results.view 內、重建必需的：

* rate inputs
* dividend inputs
* provenance
* source
* fetched/effective dates
* stale state
* engine_version
* schema_version

抽成獨立、持久化欄位／結構。

這一步完成前禁止移除 historical view。

Stage 1-1 — Dual-write

舊完整 historical representation 照寫，同時寫新 narrow history / seed representation。

Stage 1-2 — Parity proof

證明新資料足以支援既有 historical UI 與 re-analysis contract。

Stage 1-3 — Switch read path

歷史讀取切到 narrow representation。

Stage 1-4 — Production validation

驗證：

* UI 無退化
* history 正確
* current analysis bitwise/contract behavior 不變
* DB read volume 明顯下降
* latency 不得惡化

確認 production 穩定後，才停止寫入不再需要的 historical derived payload。

Stage 1-6 — Cleanup

最後才允許不可逆 cleanup。

* raw snapshots 不得刪
* narrow visible-candidate history 不得刪
* current result view 不得瘦身

═══════════════════════════════════════════════════════════════

  429、拿到 Retry-After 34 秒之後，下一個 symbol group 是**另
  一次 invocation**——它不知道剛剛發生過什麼。

  官方原文是 "can share"，不是 "will"；而且本輪 targeted
  research 連「production 到底有沒有開 fluid compute」都
  NOT_CONFIRMED）。所以「用行程內變數記住 blocked_until」這條路
